# 2026-10-12 平台加载反馈处理

## 现场证据

- Nginx、Risk BI、MyWorkflow 服务 active，首页和现有静态资源可正常返回 200，磁盘空间正常。
- 用户浏览器在 10:14 对新版 `index-CBixuxr4.js` 多次发起请求，分别传输约 116KB、179KB、353KB，随后完整传输约 642KB；后续 10:15 登录状态与模型接口成功返回。这支持资源下载中断或慢加载的判断，尚无用户截图确认全部症状。
- 旧入口把所有页面和完整图表库打包到一个约 2MB 原始 JavaScript 中，gzip 约 642KB，每次页面小改动都会改变该文件哈希。

## 修改

1. 页面使用 React lazy / Suspense，登录和导航不依赖模型图表下载；打开对应页面才读取页面模块。
2. 生命周期导航配置抽到独立小模块，避免侧栏导入整个图表页面；保留原导出供现有调用兼容。
3. React、图表库、动画、图标及 CommonJS 辅助函数分别分包，沿用 Nginx 已有长期哈希缓存。模块匹配严格限定真实 npm 包路径，避免把 `@floating-ui/react-dom` 错分入 React 核心。
4. 页面模块加载期间有明确提示；慢加载可重新加载。根错误边界在 React 错误时显示恢复入口。
5. API 返回坏 JSON 时抛出可见错误，不再伪装为空数据对象；合法 204 仍按原空对象行为处理。

## 构建与发布

- 启动入口及 HTML 预加载 JavaScript，gzip level 5 合计约 132,571 字节；旧单文件为 641,894 字节。此数字不包括认证后对应页面及图表库的首次下载，不是完整图表页面的总流量。
- 新入口 `index-9nK1A3j9.js`，图表库 `vendor-charts-BzLyExSB.js`。
- 预发布构建无循环 chunk 警告；匿名登录页不下载图表库。登录后模型三个页签、其它主要页面正常，脚本错误为空。
- 发布新静态资源后原子替换 HTML，保留旧资源。端口 80 的实际资源内容与构建哈希一致；HTML 保持 no-cache。
- 发布后通过实际 IP 和端口 80 观察：匿名登录页正常且未下载图表库；已登录模型页约 0.88 秒显示，稳定性 8 个图表、客群变化 7 个图表，浏览器脚本错误为空。该耗时来自服务器侧浏览器，不代表用户网络耗时。
- 未运行测试套件，未触发业务计算或发送通知；浏览器观察使用现有登录配置，临时会话随后退出。
