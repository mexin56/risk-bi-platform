# 模型分监控计算与展示解耦实施计划

**目标：** 模型分监控由 MyWorkflow 计算并发布 DuckDB 业务结果，Risk BI 页面只读取已发布数据，筛选和刷新均不触发上游 SQL。

## 设计

- 沿用现有模型字段、去重、AUC/KS、成熟度阈值和 qcut10 口径。
- 核心聚合使用多维分组批量计算客户类型、产品、服务节点的全部有效筛选组合，保留去重统计的准确性。
- qcut10 在筛选组合、模型、业务环节内独立分箱；保留每日客户最新记录选择和原排序规则。
- 在 `model_serving/results.duckdb` 完成业务结果，再经共同发布锁与原子替换发布到 `risk_bi_platform.duckdb`；授信、资金和模型结果互相保留。
- 公共库仅增加 `model_` 前缀业务结果表；旧 JSON 缓存作为历史初始化来源，不作为页面回退计算入口。
- 页面读取物化结果，按文件版本缓存编码响应，支持压缩、ETag；页面使用紧凑载荷省去没有展示的每日效果数组。
- 新建英文工作流 `risk-bi-model-monitoring-daily`，每天 14:30（Asia/Shanghai），处理前一天分区，日志与业务代码可查看。
- 下线同名旧 Dagster 模型调度，保持原授信和资金调度。
- 无已发布结果的分区或筛选明确提示在 MyWorkflow 运行计算，不回退上游查询。

## 约束

- 保持端口 80 的现有 Nginx 路径，不安装数据库服务。
- 不新增或运行测试套件，不发送钉钉通知。
