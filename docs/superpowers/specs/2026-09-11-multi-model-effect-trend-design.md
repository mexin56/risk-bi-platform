# 多模型业务效果趋势监控设计

## 目标

基于 `pb_biz_credit.ng_cash_model_monitoring_df`，将所有字段名以 `_score` 结尾的字段视为模型分，比较不同模型在时间维度上的区分能力变化。页面保留业务环节总览，但主视图改为“模型 × 日期”的效果趋势。

## 数据与口径

- 时间字段：`event_date`。
- 模型字段：表中所有已确认的 `_score` 字段；模型字段当前为 `STRING`。
- 无效分数：空值、NULL、`-1` 不进入模型效果计算；`-1` 单独计入模型覆盖质量。
- 目标标签：
  - FPD7：`fpd7_fm_dd=1` 为成熟观察样本，`fpd7_fz_dd=1` 为坏样本。
  - FPD30：`fpd30_fm_dd=1` 为成熟观察样本，`fpd30_fz_dd=1` 为坏样本。
  - TERM3：`term3_fm_dd=1` 为成熟观察样本，`term3_fz_dd=1` 为坏样本。
- 成熟度：当某天目标标签成熟样本数 / 当天放款成功数低于 50%，或成熟样本数低于 1,000 时，该天该目标的 AUC/KS 置空并标记“成熟度不足”。

## 效果计算

为控制 MaxCompute 扫描结果规模，按每个模型的分数以 50 分为一个桶（0-49、50-99……900+），先在 MaxCompute 按“日期、模型、分数桶”聚合成熟样本数和坏样本数，再在服务端计算近似 AUC 和 KS。

- AUC：按分数桶累计好/坏样本，计算坏样本相对好样本的排序概率；同时使用 `max(AUC, 1-AUC)`，不预设“分数越高风险越高/越低”的方向。
- KS：按分数桶累计坏样本率和好样本率的最大绝对差。
- 每个日期、每个模型、每个目标输出：`auc`、`ks`、`mature_count`、`bad_count`、`score_valid_count`、`score_coverage`、`maturity_warning`。
- 没有有效分或没有足够好/坏样本的模型，保留在覆盖率表中，但效果指标为空，不补零。

## 页面设计

1. 顶部数据源、分区和刷新状态。
2. 业务环节概览卡：审批通过率、放款成功率、FPD7/FPD30/TERM3 成熟样本坏账率。
3. 主图“多模型效果趋势”：
   - 指标切换：AUC、KS。
   - 目标切换：FPD7、FPD30、TERM3。
   - 默认展示有效覆盖率最高的模型，支持通过图例开关其余模型。
   - 成熟度不足日期断线；悬停显示模型、日期、效果值、成熟样本量和分数覆盖率。
4. 辅助图“模型有效分覆盖率趋势”：比较模型是否断流或空值抬升。
5. “模型最新表现”表：模型、最新可用日期、AUC、KS、成熟样本数、有效覆盖率、状态。
6. 原有分数段和业务类型分析降为辅助区，不再把 OP V2 作为唯一主模型。

## 接口与缓存

继续使用 `/api/model-monitoring`，响应增加 `model_effect_trend` 和 `latest_model_effect`，保留 `model_coverage` 与业务环节数据。查询按模型趋势做一次聚合任务，沿用服务端分区参数、15 分钟内存缓存和手动刷新机制；不返回业务号、客户号、卡号等明细标识。

## 测试与验收

- 单元测试：分桶 AUC/KS、反向分数方向、空分数、无成熟样本、成熟度不足断线。
- 数据验收：用 `pt=20260910` 真实分区核验模型数量、覆盖率、效果趋势行数和代表模型的样本总量。
- 前端验收：AUC/KS 与 FPD7/FPD30/TERM3 切换生效，缺失值显示为空，图表不把未成熟日期画成 0。
- 工程验收：Python 测试通过，TypeScript/Vite 构建通过，新文件 lint 通过。
