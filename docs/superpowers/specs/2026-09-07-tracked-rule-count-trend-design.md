# 持续观察规则计数与近 60 天趋势设计

## 目标

当规则当前状态为“进行中”（状态值 `2`），即使当前分区没有重新命中预警，也必须：

- 在“持续观察监控”中计入独立的持续观察数量；
- 保留“当前无预警”的事实，不伪装成新的 L1/L2/L3 预警；
- 允许从表格行进入路径分析，展示完整近 60 天趋势。

## 当前根因

管线已经把当前未命中的活动规则追加到 `merged_alerts`，并写入路径日序列，但只更新了 `merged_alert_total`，没有同步汇总字段。前端对 `is_tracked_only` 的 Level0 记录使用不可点击文本渲染，因此用户无法打开已存在的趋势数据。

## 设计

### 后端数据

在管线追加活动跟踪规则后，同步更新 dashboard summary 的持续观察数量字段。该字段只统计当前状态为 `2` 的活动跟踪规则，不改变 `level1_count`、`level2_count`、`level3_count`，避免把当前未命中的规则误计为实时预警等级。

合并结果继续保留 `is_tracked_only=true`、`level=0` 和 `tracking_start_pt`，路径日序列继续使用预计算的 60 天范围。现有 `/path-trend` 接口无需改变查询口径。

### 前端展示

“持续观察监控”标签使用后端持续观察数量；其余状态标签维持当前语义。持续观察但当前无预警的行仍显示 `Level0 无预警`，但路径名称改为可点击入口，复用现有趋势加载逻辑。

表格趋势入口不改变普通预警行的交互；只对 `is_tracked_only` 行放开点击。点击后请求现有路径趋势接口，默认显示 60 天，并保留 7/15/30/60 天切换。

### 失败处理

若趋势接口返回错误，沿用现有错误提示和“重新加载趋势”按钮。持续观察数量来自 dashboard 数据，趋势加载失败不影响表格行和状态筛选。

## 测试与验收

- 后端测试：活动跟踪规则追加后，summary 的持续观察数量正确，L1/L2/L3 实时预警数量不被改变。
- 前端测试/静态验证：持续观察 Level0 行使用可点击路径入口；普通 Level0 候选仍保持原有展示。
- 接口回归：`4916e4008700` 在 `pt=20260906` 可返回 60 个趋势点。
- 构建验证：TypeScript/Vite 构建通过。

## 范围

本次只调整持续观察规则的计数契约和趋势入口，不改变预警判定阈值、状态生命周期、趋势 SQL 或通知逻辑。
