# 授信归因钉钉 AI 助手设计

## 目标

在指定钉钉群内提供一个可被 `@` 的“授信归因助手”。群成员可以用自然语言询问某个 pt 的预警等级、异常规则、趋势、通过率和已打标规则表现，助手基于项目已经发布的 DuckDB/serving 数据进行只读分析，并返回带数据证据的结论。

第一版不自动修改规则状态、不执行策略变更、不执行用户提供的任意 SQL。每日钉钉日报仍由现有通知任务负责，AI 助手作为交互式查询入口。

## 方案

采用“钉钉群机器人事件接入 + 项目后端分析服务 + 模型生成回答”的方式：

```text
群成员 @授信归因助手
        ↓
钉钉机器人事件适配器
        ↓
问题意图识别与参数解析
        ↓
授信归因只读数据工具
        ↓
结构化证据 + 模型分析
        ↓
钉钉群回复（结论、证据、链接）
```

机器人接入层应使用可接收群消息的企业机器人事件/Stream 能力；现有自定义 Webhook 继续只负责日报发送，不能直接承担问答入口。

## 功能范围

### 支持的问题

- 最新可用 pt 和指定 pt 的 Level1/Level2/Level3 数量与占比
- 某条异常归因路径的命中窗口、增长、结构提升和 z-score
- 某条路径近 7/15/30/60 天的申请量与趋势
- 件数通过率、人数通过率及二者差异
- 已上策略、持续观察规则从打标 pt 开始的后续表现
- 两个 pt 之间的预警数量、等级结构和通过率变化
- 根据数据证据生成风险总结和建议关注项

### 回复格式

每次回答包含：

1. 结论：用 1～3 句话直接回答问题。
2. 数据证据：列出使用的 pt、指标、时间窗口和关键数值。
3. 原因判断：区分“数据直接证明”和“基于数据的推断”。
4. 后续建议：如核查来源、观察后续 pt 或复核策略口径。
5. 页面链接：必要时附授信归因页面和对应截图/趋势链接。

无法找到对应数据时，明确说明缺少哪个 pt、路径或预计算趋势，不编造结论。

## 后端模块

### 1. DingTalkAdapter

负责验证钉钉事件、提取群会话、发送群回复，并过滤非 `@` 消息。需要支持：

- 机器人签名/事件校验
- 群 ID 和用户 ID 白名单
- 消息去重，避免钉钉重试导致重复回答
- 回复长度限制与超时提示

### 2. AttributionQueryTools

提供固定的数据查询函数，不暴露任意 SQL：

- `latest_partition()`
- `dashboard_summary(pt)`
- `find_rules(pt, keyword, level, status)`
- `rule_detail(pt, record_id_or_path)`
- `path_trend(pt, record_id, days)`
- `tracked_rule_followup(path, start_pt, end_pt)`
- `compare_partitions(pt_a, pt_b)`

工具只读取 serving Parquet 或 DuckDB 已发布结果，优先复用现有 API/服务层，避免重新扫描 MaxCompute。返回值必须是可序列化的结构化数据，并包含数据来源和时间范围。

### 3. AttributionAgent

负责问题解析、工具调用编排和回答生成。模型输入只包含：用户问题、当前时间、允许的工具结果、回答格式约束和安全规则。模型不能接触数据库凭证，也不能自行拼接 SQL。

对于“为什么”问题，回答至少拆成：

- 观测到的事实
- 可能原因及其证据
- 当前无法确认的部分
- 建议的下一步核查

### 4. AgentAuditStore

在 SQLite 中记录：消息 ID、群 ID、用户 ID、问题、解析出的 pt/路径、调用的工具、回答状态、耗时和错误摘要。原始模型密钥、数据库密码和完整敏感数据不写入日志。

## 配置

配置只放在 `server/.env.local`，不提交仓库：

```text
DINGTALK_AGENT_ENABLED=false
DINGTALK_AGENT_APP_KEY=
DINGTALK_AGENT_APP_SECRET=
DINGTALK_AGENT_ALLOWED_GROUP_IDS=
DINGTALK_AGENT_ALLOWED_USER_IDS=
AI_AGENT_BASE_URL=
AI_AGENT_API_KEY=
AI_AGENT_MODEL=
AI_AGENT_TIMEOUT_SECONDS=30
```

默认关闭。只有完成单群测试、权限校验和回答验证后，才将 `DINGTALK_AGENT_ENABLED` 改为 `true`。

## 错误处理

- 上游或 serving 没有目标 pt：回复当前最新可用 pt，并说明目标 pt 不存在。
- 趋势数据未预计算：不实时扫描大表，提示先刷新归因结果。
- 模型超时或不可用：回复已查到的结构化指标，并提示 AI 总结暂不可用。
- 钉钉发送失败：记录错误并允许事件重试，但使用消息 ID 去重。
- 未授权群/用户：不返回业务数据，只回复无权限提示并写审计记录。

## 安全与边界

- 仅允许指定群和指定用户使用。
- 只读查询，不允许通过聊天修改状态、上策略或删除记录。
- 不接受自然语言 SQL，不把数据库连接或 MaxCompute 凭证交给模型。
- 回答中不输出手机号、身份证号、设备号等个人明细，只输出聚合后的归因指标。
- 每条回答标注数据 pt 和时间窗口，避免把推断表述成确定事实。

## 验证标准

- 未配置凭证或开关关闭时，服务启动不失败，机器人入口不处理业务消息。
- 白名单群内 `@机器人` 能正确提取问题并返回回答；非 `@` 消息不触发。
- 对最新 pt、指定 pt、规则路径、趋势和通过率问题分别有固定测试样例。
- 工具调用只访问白名单函数，任意 SQL/越权参数被拒绝。
- 同一消息重试不会重复回答。
- 模型失败时仍能返回结构化查询结果或明确错误提示。
- 现有归因、趋势预计算、钉钉日报和页面功能测试不受影响。

## 分阶段交付

1. 先实现只读查询工具和本地模拟问答，不连接钉钉。
2. 接入一个测试群，限制单群、管理员用户，并验证 5 类典型问题。
3. 增加趋势链接、风险总结和审计查询。
4. 通过测试后再启用正式群和生产模型配置。
