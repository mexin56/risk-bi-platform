# 当前打标规则后续跟踪统计设计

## 目标

对当前处于“已上策略”(status=1)或“持续观察”(status=2)的规则，从该次状态进入的 `entered_pt` 开始持续跟踪后续每个 pt。规则后续某天即使不再命中发现规则，也必须保留当天的件数、人数、通过率和趋势数据。

## 口径

- 每次进入 status=1 或 status=2 都建立一个新的统计起点。
- 当前有效区间的起点为状态历史表中该规则未退出的记录的 `entered_pt`。
- 统计包含 `entered_pt` 当天；切换状态前的数据不计入当前状态。
- 规则当天未命中时，写入申请量、通过量、cid 数和通过 cid 数均为 0 的日记录。
- 同一路径只保留当前有效状态的一条跟踪记录，历史区间留在“打标记录”中。
- 所有跟踪数据继续写入 DuckDB 并由 serving 快照提供，页面不实时扫描 MaxCompute。

## 数据流

1. 预计算任务从 SQLite 状态历史读取当前未退出的 status=1/2 记录，并取得每条规则的 `entered_pt`。
2. 复用现有批量路径聚合，得到全量趋势窗口。
3. 对跟踪规则过滤 `date < entered_pt` 的序列；当前命中规则也使用过滤后的序列重新生成窗口指标，未命中规则则生成 tracked-only 记录。
4. `path_daily` 从 `entered_pt` 开始写入每日记录，缺失命中日补 0，继续保存件数、人次和两种通过率所需的原始计数。
5. 页面读取当前状态规则时展示过滤后的预计算指标；趋势接口只返回起点之后的数据。

## 兼容与异常

- 旧状态表中没有历史区间的 status=1/2 记录继续兼容：使用当前状态的 `action_date` 作为起点；若没有起点，则使用当前 pt，避免混入未知的历史数据。
- 历史记录缺少完整规则定义时不执行路径聚合，并保留现有打标记录展示。
- 起点晚于当前趋势窗口时，保留起点当天及之后可取得的数据；基准窗口为空时沿用现有无基准口径。

## 验证

- 单元测试验证起点前数据被排除、起点当天和后续 0 值被保留。
- 单元测试验证 status=1 切换 status=2 后使用新的起点。
- 运行现有授信归因、DuckDB 趋势、人数通过率和调度测试。
- 构建前端并检查 serving 快照读取链路不回退到实时查询。
