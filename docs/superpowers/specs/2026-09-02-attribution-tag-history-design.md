# 授信归因规则打标历史设计

## 目标

在授信归因监控页增加“打标记录”Tab，完整记录规则进入和离开“已上策略”“持续观察”的时间、对应 `pt`、操作人和当前状态；现有状态 Tab 继续展示当前状态。措施日期改为执行本次标记时页面选中的 `pt` 日期，不再使用服务器系统日期。

## 方案

采用现有 SQLite 状态库新增历史表的方式。`attribution_rule_status` 保留每条规则的最新状态，新增 `attribution_rule_status_history` 保存状态区间。这样当前页面查询仍然轻量，历史 Tab 可以按时间和 `pt` 查询，也不会依赖日志完整性。

不新增第三方依赖；历史记录和当前状态继续由 `server/attribution_status.py` 统一维护。

## 数据模型

历史表保存状态为 1 或 2 的每个连续区间：

- `id`：自增主键
- `canonical_path`：规则唯一路径
- `status`：1 表示已上策略，2 表示持续观察
- `rule_json`：状态进入时的规则快照
- `entered_at`：系统记录的实际操作时间，用于审计排序
- `entered_pt`：进入状态时页面选中的分区值，例如 `20260831`
- `entered_by`：进入状态的操作人
- `exited_at`：移出该状态的实际操作时间，仍在状态中时为空
- `exited_pt`：移出状态时页面选中的分区值，仍在状态中时为空
- `exited_by`：移出该状态的操作人，仍在状态中时为空

现有最新状态表的 `action_date` 改为保存当前状态的 `entered_pt`。历史表以 `(canonical_path, status, entered_at)` 的实际记录为准，状态表只作为当前页面快速展示的数据源。

## 状态变更规则

接口请求必须携带 `action_pt`，后端原样保存规范化后的 `pt` 字符串，并拒绝空值。

1. `0 → 1/2`：新增一条历史区间，填写 `entered_at`、`entered_pt`、`entered_by`。
2. `1/2 → 0`：关闭当前未结束区间，填写 `exited_at`、`exited_pt`、`exited_by`。
3. `1 → 2` 或 `2 → 1`：先关闭旧区间，再新增目标状态区间。
4. `1 → 1` 或 `2 → 2`：不新增区间，保留原进入时间和进入 `pt`，只更新当前状态的规则快照。
5. `0 → 0`：不产生历史记录。

这样每次进入和移出都可追溯；同一规则重新进入同一状态时会产生新的历史区间。

## 接口和数据流

- `PUT /api/credit-attribution/rule-status`
  - 请求增加 `action_pt`
  - 后端在一个 SQLite 事务中更新最新状态、关闭旧区间或创建新区间
  - 返回最新状态、`action_date=action_pt`，以及本次变更对应的历史记录
- `GET /api/credit-attribution/rule-status-history`
  - 返回所有历史区间，按 `entered_at` 倒序
  - 每条记录返回规则路径、状态标签、进入/移出时间、进入/移出 `pt`、操作人和是否仍在该状态

状态下拉保存失败时，页面保留原状态并显示现有错误提示；历史查询失败时不阻塞当天归因结果，Tab 显示错误提示并允许重新加载。

## 页面行为

现有三个 Tab 保持不变，并新增第四个 Tab：`打标记录`。

- `发现规则`：仍展示当天 `pt` 的异常规则，不受规则当前状态影响；不显示措施日期。
- `已上策略`：只展示当前状态为 1 的规则；“措施日期”显示进入该状态时的 `pt`。
- `持续观察监控`：只展示当前状态为 2 的规则；“措施日期”显示进入该状态时的 `pt`。
- `打标记录`：展示历史表全部区间；使用“进入时间/进入 pt”和“移出时间/移出 pt”两组列，不显示系统当天生成的措施日期。

用户在任意状态 Tab 修改下拉框时，页面将当前 dashboard 的 `meta.partition` 作为 `action_pt` 发送。更新成功后同步更新当前表格、当前选中规则和打标记录 Tab。

## 测试和兼容性

- SQLite 单元测试覆盖首次进入、移出、1/2 互切、重新进入、相同状态重复标记，以及 `action_pt` 保存。
- 接口模型测试覆盖缺少 `action_pt` 和空 `action_pt` 的拒绝行为。
- 前端构建检查类型和 Tab 渲染；浏览器验证四个 Tab、措施日期列条件显示及历史记录列。
- 旧状态库迁移时保留已有最新状态；旧记录的 `action_date` 仅在已有值为空时保留兼容性回填，新的更新全部使用请求中的 `action_pt`。
